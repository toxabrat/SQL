# Учебная база данных на C++

Совместный учебный проект: собственная база данных с хранением таблиц в оперативной памяти и парсером SQL-подобного языка на C++17. Проект показывает, как текст запроса превращается в операции над таблицами без использования готовой СУБД.

## Как это работает

1. `Tokenizer` разбивает запрос на ключевые слова, имена столбцов, литералы и операторы.
2. `Parser` и `MathParser` разбирают запрос и выражения в условии, создавая объекты запросов и операций.
3. `Query::executeQuery()` выполняет запрос над объектом `DataBase`.
4. `DataBase`, `Table`, `Row` и `Object` хранят таблицы, метаданные столбцов, строки и типизированные значения в памяти.

## Основные части

- Создание таблиц, вставка данных, выборка столбцов с фильтрацией и удаление строк по условию.
- Разбор арифметических выражений, сравнений и логических операций в условиях.
- Операции соединения таблиц и обновления строк в ядре БД.
- Типы данных `int32`, `bool`, `string` и `bytes`, метаданные столбцов, проверки типов, атрибутов и значений по умолчанию.
- Тесты на GoogleTest для объектов, метаданных, работы с таблицами и выполнения запросов через парсер.

## Пример запросов

Минимальный сценарий из `tests/Test.cpp`:

```sql
CREATE TABLE student ( id: bool )
INSERT (true) TO student
SELECT id FROM student WHERE true
DELETE student WHERE true
```

Каждая строка передаётся парсеру отдельно. В этом диалекте используются `имя: тип` при объявлении столбца, `INSERT (...) TO таблица` для вставки и `DELETE таблица WHERE условие` для удаления. Ключевые слова запросов пишутся в верхнем регистре, типы и булевы значения - в нижнем. У `SELECT` условие `WHERE` обязательно.

Пример вызова из C++:

```cpp
auto database = std::make_shared<DataBase>();
std::string sql = "CREATE TABLE student ( id: bool )";
auto query = Parser(Tokenizer(sql)).parse_query(sql);
query->executeQuery(database);
```

## Сборка и запуск тестов

Нужны компилятор с поддержкой C++17 и CMake 3.16 или новее. GoogleTest загружается автоматически через CMake FetchContent, поэтому при первой конфигурации требуется доступ к GitHub.

```bash
cmake -S . -B build
cmake --build build --target unit_test
./build/unit_test
```

В текущей версии примеры работы с БД находятся в тестах. `main.cpp` пока содержит заготовку, поэтому для запуска собирается цель `unit_test`. Обработчик `UPDATE` есть в ядре, но его разбор из текста запроса ещё не подключён.

## Структура репозитория

- `table/` - хранение данных, метаданные и операции над таблицами.
- `parser/` - токенизатор, объекты запросов, условий и выражений.
- `parser/parse_factory/` - разбор текста запросов и выражений.
- `tests/` - тесты и примеры использования.
